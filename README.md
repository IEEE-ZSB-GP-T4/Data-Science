## 🔗 Integration Guide (Frontend & Backend Workflow)

This section explains how the Data Science module integrates with the *Laravel 12 (Backend)* and *React (Frontend)* applications. 

The Python script handles all complex calculations, data aggregations, and visual configurations, outputting a highly standardized JSON response.

### 1. Data Science Role (Python)
The src/connect.py script acts as the main entry point. When executed, it pulls the data, processes the KPIs, and generates Plotly chart configurations (including our custom Planora color palette). 
* *Output:* A strict RESTful JSON format containing status, message, and data (KPIs + Visuals configurations).


### 2. Backend Role (Laravel 12)
The Laravel backend does *not* need to recalculate any metrics or format any charts. Its role is simply to act as a bridge.


*How to integrate:*
Laravel can execute the Python script using the Process facade and serve the resulting JSON directly to the React Frontend.

```php
use Illuminate\Support\Facades\Process;

// Inside your Laravel Controller
public function getDashboard($userId) 
{
    // Run the Python script (ensure the venv python is used on the server)
    $result = Process::run("python path/to/src/connect.py {$userId}");
    
    if ($result->successful()) {
        $dashboardData = json_decode($result->output(), true);
        return response()->json($dashboardData);
    }
    
    return response()->json(['error' => 'Failed to process data'], 500);
}
```

### 3. Frontend Role (React)
The React frontend does not need to build charts from scratch using raw data. The JSON already contains the exact structure (data and layout) required by Plotly.

*How to integrate:*

**Install the Plotly React wrapper:**

```Bash
npm install react-plotly.js plotly.js
Fetch the JSON via Axios and pass it directly to the Plotly component:

```jsx

import React, { useEffect, useState } from 'react';
import Plot from 'react-plotly.js';
import axios from 'axios';

const Dashboard = ({ userId }) => {
    const [dashboardData, setDashboardData] = useState(null);

    useEffect(() => {
        axios.get(/api/dashboard/${userId}).then(response => {
            // response.data points to the JSON generated by Python
            setDashboardData(response.data.data.dashboard); 
        });
    }, [userId]);

    if (!dashboardData) return <div>Loading...</div>;

    // Extract Donut chart JSON
    const donutChart = dashboardData.visuals.tasks_status_donut;

    return (
        <div className="dashboard-container">
            {/* Render KPIs */}
            <div className="kpi-cards">
                <h3>Completion Rate: {dashboardData.kpis.task_completion_rate}%</h3>
                {/* ... other KPIs ... */}
            </div>

            {/* Render Visuals (Magically renders with colors, titles, and labels) */}
            <div className="chart-container">
                <Plot '100%' '100%', data="{donutChart.data}" height: layout="{donutChart.layout}" style="{{" useResizeHandler="{true}" width: }}/>
            </div>
        </div>
    );
};

export default Dashboard;
```

## Branching Strategy

We follow a three-tier branching model: **feature branches → dev → main**

### Branches

- **`main`** — production-ready code only. Always stable and deployable.
- **`dev`** — integration branch. All finished features are merged here first for testing before going to `main`.
- **`feature/<name>`** — individual work branches. Each team member works in their own feature branch.

### Workflow

1. **Work and commit on your branch:**

2. **Open a Pull Request into `dev`** (not `main`) once your feature is complete and tested.

3. **After review/approval**, merge into `dev`. Delete the feature branch after merging.

4. **Periodically**, once `dev` is stable and tested as a whole, the team lead opens a PR from `dev` → `main` to release.

### Rules

- Never commit directly to `main` or `dev`.
- Always pull the latest `dev` before branching off.
- Open a PR for every merge — no direct pushes to shared branches.
- Resolve merge conflicts locally before opening a PR.
